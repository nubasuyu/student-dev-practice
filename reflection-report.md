# Reflection Report

Learning Git, Continuous Integration (CI), and Quality Assurance (QA) tools presented some initial challenges. Git was difficult at first because understanding repositories, commits, branches, and merge conflicts required practice. Resolving merge conflicts was especially challenging because multiple changes in different branches sometimes created confusion.

The CI pipeline helped streamline development because it automated repetitive tasks. Every time code was pushed to GitHub, the pipeline automatically checked the code quality and executed tests. This reduced the need for manual testing and immediately identified errors before they became larger problems.

Version control significantly improved collaboration because multiple students could work independently on separate branches while maintaining a stable main branch. Branching allowed new features to be developed safely without affecting existing functionality.

Quality assurance practices also improved the project's overall quality. Writing unit tests ensured that functions worked as expected, while ESLint identified formatting and coding issues early. Peer code reviews provided additional feedback and helped improve coding standards and readability.

Overall, these tools demonstrated how software teams maintain organized workflows and produce reliable applications through collaboration and automation.
